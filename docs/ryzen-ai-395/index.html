Ryzen AI Max+ PRO 395 LLM benchmarks

Seven models from 9B to 35B parameters, each small enough for the 32 GiB BIOS VRAM carve-out, run fully on the integrated GPU with llama.cpp (Vulkan and ROCm) and compared against Ollama. Peak GPU memory was sampled during every run to see where each engine puts the model.

Recommended settings

To keep models inside the 32 GiB carve-out, serve them with the Vulkan build. It also generates fastest here on every model.

./scripts/check-ryzen-ai.sh             # read-only setup check
./scripts/build-ryzen-ai-vulkan.sh      # -> build-vulkan

build-vulkan/bin/llama-server -m model.gguf -ngl 99 -fa on -ub 2048 -b 2048 --jinja
#   + --spec-type draft-mtp          for models with an MTP head (Qwen3.8-27B): 12.4 -> 26.7 tok/s

The Vulkan peak was 19.8 GiB in the carve-out (Qwen3.6-35B-A3B at 16k context), so every model here leaves room for a longer context. ROCm and Ollama do not use the carve-out at all, see below.

Findings

  • Only Vulkan uses the carve-out. llama.cpp Vulkan placed every model in VRAM, with under 1.2 GiB in shared RAM. llama.cpp ROCm and Ollama (also ROCm) placed every model in shared system RAM (GTT) and left VRAM at its idle 0.5 GiB. With those engines the carve-out stays reserved and unused, and the model takes memory from the 92 GiB the OS has.
  • Nothing caps ROCm or Ollama at 32 GiB. /etc/modprobe.d/ttm.conf sets ttm pages_limit=26214400, so ROCm and Ollama report 100 GiB of GPU memory and Vulkan reports 124 GiB. A model larger than the carve-out would load and spill instead of failing.
  • Vulkan generates fastest on every model. It generates 8-85% faster than Ollama and 3-51% faster than llama.cpp ROCm. The gap is largest on the MoE models (gpt-oss-20b +85% vs Ollama) and smallest on the dense Mistral-Small-24B.
  • Prompt processing follows the same order but closer. Vulkan leads Ollama by 2-39% and ROCm by up to 33% (the two tie on Mistral-Small-24B); Qwen3.6-35B-A3B has the widest gap.
  • MTP drafting makes Qwen3.8-27B fast. Ollama's file has the MTP head and Ollama uses it. llama.cpp with --spec-type draft-mtp on the same file reaches 26.7 tok/s on Vulkan, against 20.3 for Ollama and 12.4 without drafting; 61-71% of drafted tokens were accepted. The ggml-org Q4_K_M has no MTP layers.
  • Ollama's files load in llama.cpp for 3 of the 7 models. qwen3.5, gpt-oss, gemma4 and qwen3.6 use Ollama-only metadata (for example gptoss as the architecture name); llama.cpp ran a public GGUF with the same quantization for those.
