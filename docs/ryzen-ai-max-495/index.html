Recommended settings

Build both backends with the branch scripts, then serve with Vulkan, all layers on the GPU, flash attention and a 2048-token micro-batch. These are the settings the headline numbers below were measured with.

./scripts/build-ryzen-ai-vulkan.sh      # -> build-vulkan  (Release, GGML_NATIVE, OpenMP)
./scripts/build-ryzen-ai.sh             # -> build-rocm    (Release, GGML_NATIVE, HIP graphs, gfx1151)

build-vulkan/bin/llama-server -m model.gguf -ngl 99 -fa on -ub 2048 -b 2048 --jinja
#   + --spec-type draft-mtp          for models with an MTP head (Qwen3.5-122B)
#   + -ctk q8_0 -ctv q8_0            to halve KV cache memory for about 1% speed

Do not use the EAGLE3 draft heads for gpt-oss: they made generation equal or slower and prompts 13% slower. CPU-only inference is not practical: with the 160 GiB carve-out the OS keeps about 30 GB, and gpt-oss-20b on the CPU generates 31.7 tok/s versus 76.9 on the GPU.

Findings

  • Vulkan is the best backend. It generates 3-19% faster than ROCm on all ten chat models and processes prompts faster on all of them except MiniMax-M2.1.
  • -ub 2048 -b 2048 is free speed for prompts. On a 2.5-3k token prompt it raised Vulkan prompt speed 9-61% with no change to generation.
  • Generation speed follows active parameters, not model size. Generation is memory-bandwidth bound, so MiniMax-M2.1 (230B total, 10B active) beats GLM-4.5-Air (106B, 12B active), and Qwen3-235B still reaches 17.4 tok/s.
  • MTP speculative decoding pays off. Qwen3.5-122B goes from 27.5 to 43.4 tok/s with about 80% draft acceptance. EAGLE3 for gpt-oss accepts only about 50% and does not help.
  • llama.cpp beats Ollama on 3 of 4 models. gpt-oss-20b generates 56% faster; the Qwen models tie on generation but prompt 36-40% faster. Nemotron is the exception, explained by its quantization below.

Why Nemotron is slower in llama.cpp

The unsloth UD-Q4_K_M file keeps the dense layers, which are read for every token, at Q8_0. Ollama's file quantizes them to Q4_K. Per token, llama.cpp reads about 10.7 GB of weights against Ollama's 7.7 GB, which accounts for most of the gap. A plain Q4_K_M GGUF would likely close it.

After merging upstream master
