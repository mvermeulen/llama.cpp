Ryzen AI Max PRO 390 LLM benchmarks

The same seven models from 9B to 35B parameters as the mev_ryzen395 report, run fully on the integrated GPU with llama.cpp (Vulkan and ROCm) and compared against Ollama, on the smaller Strix Halo part with 64 GB and a 32 GiB BIOS VRAM carve-out. Peak GPU memory was sampled during every run, and three models were also run with MTP speculative decoding.

Recommended settings

Serve models with the Vulkan build; it generates fastest on every model. Add an MTP draft where one exists, it is the biggest single gain.

The largest model here peaked at 20.2 GiB in the carve-out with llama.cpp (22.6 GiB with Ollama) at 16k context, so about 10 GiB is left for longer contexts.

Findings

  • All three engines use the carve-out. Unlike the 395, where llama.cpp ROCm and Ollama put every model in shared RAM (GTT), here ROCm and Ollama place it in VRAM like Vulkan does. ROCm appears to use the larger of the two memory pools: here it reports the 32 GiB carve-out as device memory, since GTT is at its default of half the 30.4 GiB the OS sees (15.2 GiB); the 395 had ttm.pages_limit raised so ROCm reported 100 GiB of GTT.
  • Generation matches the 395, prompts do not. Both parts have the same 256-bit memory bus, and generation is memory bound: Vulkan generation is +2% vs the 395 (geometric mean). Prompt processing is compute bound and the 8050S has 32 CUs against 40: Vulkan prompts are -18%, ROCm -11%.
  • Vulkan generates fastest on every model, +19% over llama.cpp ROCm (geometric mean, 5-38% per model). The gap is largest on the MoE models and smallest on the dense ones.
  • ROCm now leads on prompts for the dense models. ROCm processes prompts 3-6% faster than Vulkan in the server runs on Qwen3.5-9B, Mistral-Small-24B, Qwen3.8-27B and Gemma-4-26B-A4B, and 7-12% faster in llama-bench at 4096 tokens. Vulkan leads on gpt-oss-20b (+8%) and Qwen3.6-35B-A3B (+2%); Qwen3-Coder-30B-A3B is within 2.5% either way. On the 395 Vulkan led or tied on every model.
  • Ollama now drafts with MTP on Gemma-4 and Qwen3.8. The current gemma4:26b pulls a separate 0.46 GB MTP draft (74-78% acceptance in Ollama's log), which lifts it to 64.2 tok/s, ahead of plain llama.cpp (53.5). With ggml-org's public draft and --spec-type draft-mtp -md, llama.cpp Vulkan reaches 74.9 tok/s.
  • MTP drafts add 36-103% generation. Most on the dense Qwen3.8-27B (Vulkan 12.5 -> 25.3), 36-40% on the Vulkan MoE runs and 61-72% on ROCm. Prompt speed drops 0.5-6%.
  • -ub 2048 helps MoE models, not dense ones on ROCm. At 4096 prompt tokens it gains 11-27% over -ub 512 on MoE models with Vulkan and 3-15% with ROCm; dense models change by -4 to +13%, and ROCm is 1-4% slower on all three dense models.
